# 舞台演出串联与提示表编辑器

导演和舞台监督使用的纯前端提示表工作台。可按幕、场和提示点维护演出流程，拖动后自动顺延后续时间，并持续检查负责人、时间、道具、演员和引用关系。

## 功能

- 按幕、场维护开场时间、灯光、音响、道具、演员、负责人和工作备注。
- 提示点原生拖拽排序；调整后自动重算当前场后续提示时间。
- 检查负责人空缺、同场时间冲突、跨场道具撞场、演员撞场及已删除提示的失效引用。
- 复制上一场完整流程，并自动生成独立提示 ID。
- 锁定场次或保存锁定版本，从历史版本建立可编辑修订。
- 选择锁定版本后按提示逐条比较负责人、时长和流程差异。
- 文档级撤销/重做、键盘顺序调整、搜索和浏览器本地持久化。
- 可交互的首演示例数据覆盖两个场次、多类提示和待处理问题。

## 换场单合并

演出当晚前台改灯光道具、后台下发换场单，两边可离线处理，回来再合并。状态所有权清晰划分：

- **换场单只提供事实**：场次顺序、上下场、人员到场。
- **本地提示表负责编排**：灯光、音响、道具、时长、负责人、备注、提示顺序。

合并规则：

- 合并只写事实字段；同一提示的核心字段（上下场 / 人员）出现分歧时，本地值与下发值**并列保留**为冲突记录，绝不自动覆盖，由人工取舍。
- 换场单更新后，只有受影响的**未确认**提示按新修订重新核对；已确认内容保留旧依据。
- 合并按批次逐条推进，每条落盘一次：合并失败后保留进度与成功回执，重试同一批不会重复生成提示；页面中途关掉再打开，会从上次批次游标接着处理。
- 旧数据没有来源标记时，一律按本地已确认处理。

右栏「换场单合并」面板可接收示例批次、开始/继续合并、处理分歧并列、核对确认待核对提示。

## 技术栈

- Ember 5
- TypeScript
- Ember Paper
- Glimmer 组件
- 原生 `localStorage`

## 本地开发

```bash
npm install
npm start
```

浏览器打开终端输出的开发地址。

## 生产构建

```bash
npm run build
```

生产文件位于 `dist/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `Alt + ↑ / ↓` | 将当前提示前移或后移 |
| `N` | 新建提示（表单编辑区域外） |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |

## Docker

容器内由 nginx 监听端口 `80`，源码不硬编码宿主端口。

```bash
docker build -t stage-cue-prompt-editor .
docker run --rm -p 10013:80 stage-cue-prompt-editor
```

宿主端口 `10013` 仅作为本地运行示例，实际端口由根编排文件统一管理。
