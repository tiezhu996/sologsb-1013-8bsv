# 舞台演出串联与提示表编辑器

导演和舞台监督使用的纯前端提示表工作台。可按幕、场和提示点维护演出流程，拖动后自动顺延后续时间，并持续检查负责人、时间、道具、演员和引用关系。

## 功能

- 按幕、场维护开场时间、灯光、音响、道具、演员、负责人和工作备注。
- 提示点原生拖拽排序；调整后自动重算当前场后续提示时间。
- 检查负责人空缺、同场时间冲突、跨场道具撞场、演员撞场及已删除提示的失效引用。
- 复制上一场完整流程，并自动生成独立提示 ID。
- 锁定场次或保存锁定版本，从历史版本建立可编辑修订。
- 选择锁定版本后按提示逐条比较负责人、时长和流程差异。
- 文档级撤销/重做、键盘顺序调整、搜索和浏览器本地持久化。
- 可交互的首演示例数据覆盖两个场次、多类提示和待处理问题。

## 后台换场单与本地提示表（离线合并）

系统严格区分两侧状态所有权，支持两边各自离线处理后再合并：

| | 后台换场单（事实层） | 本地提示表（编排层） |
| --- | --- | --- |
| 拥有 | 场次顺序与场次结构、提示核心字段事实、上下场与人员到场 | 提示排序、时间轴（offset）、工作备注、前置依赖、锁定、核对与确认 |
| 规则 | 只读下发，不持有任何本地状态 | 负责编排与逐条确认，可对事实做「保留本地 / 采用事实」的字段级决定 |

- **字段分歧并列保留**：同一条提示的核心字段（类型、标题、时长、负责人、灯光、音响、道具、演员）与换场单不一致时，本地值与事实值连同各自依据版本并列展示，**绝不自动覆盖**，只能人工逐字段裁决。
- **按影响范围重新核对**：换场单更新后，只有受影响且未确认的提示进入重新核对队列；已确认内容保留旧依据，仅在「新版事实」区列出差异，是否复审由人决定。
- **可恢复的批次合并**：每个换场单版本是一个批次，按提示逐条处理并实时落盘。处理中断时保留进度与已成功回执；重试同一批跳过已处理提示，不重复生成；页面中途关掉再打开会从上次批次断点继续（进行中自动续跑，失败态等待手动重试）。
- **旧数据兼容**：没有来源标记的历史数据按「本地确认」处理。

界面中可接收示例换场单 `GS-V1` / `GS-V2`（V2 含灯光修订、人员到场变更与新增候场提示），并可勾选「演示下一批中断」验证保留进度、重试幂等与断点续跑。

## 技术栈

- Ember 5
- TypeScript
- Ember Paper
- Glimmer 组件
- 原生 `localStorage`

## 本地开发

```bash
npm install
npm start
```

浏览器打开终端输出的开发地址。

## 生产构建

```bash
npm run build
```

生产文件位于 `dist/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `Alt + ↑ / ↓` | 将当前提示前移或后移 |
| `N` | 新建提示（表单编辑区域外） |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |

## Docker

容器内由 nginx 监听端口 `80`，源码不硬编码宿主端口。

```bash
docker build -t stage-cue-prompt-editor .
docker run --rm -p 10013:80 stage-cue-prompt-editor
```

宿主端口 `10013` 仅作为本地运行示例，实际端口由根编排文件统一管理。
